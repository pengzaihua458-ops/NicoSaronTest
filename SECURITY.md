# Security Policy

## Supported Versions

We provide security updates for the following versions of our project:

| Version | Supported |
| ------- | --------- |
| 1.0.x   | ✅ Yes    |
| < 1.0.0 | ❌ No     |

## Reporting a Vulnerability

We take the security of our project seriously. If you believe you have found a security vulnerability, please report it to us by following these steps:

1. **Preferred Method**: Open a report via [GitHub Security Advisories](https://github.com/pengzaihua458-ops/NicoSaronTest/security/advisories/new). This is the most secure and efficient way to disclose a vulnerability.
2. **Alternative Method**: Email your findings to [security@example.com](mailto:security@example.com) using the template below.

### Disclosure Policy

- **Acknowledgment**: We will acknowledge receipt of your report within **48 hours**.
- **Initial Assessment**: We aim to provide an initial assessment of the vulnerability within **7 business days**.
- **Public Disclosure**: We ask that you do not disclose the vulnerability publicly until we have had a chance to address it.

### Reporting Template

When reporting a vulnerability, please include as much of the following information as possible to help us triage and resolve the issue quickly:

- **Vulnerability Type**: (e.g., XSS, SQL Injection, Buffer Overflow)
- **Severity**: (e.g., Critical, High, Medium, Low)
- **Affected Component(s)**: (e.g., specific library, API endpoint, or UI component)
- **Description**: A clear and concise description of the vulnerability.
- **Steps to Reproduce**: Detailed steps that someone else can follow to reproduce the issue.
- **Proof of Concept (PoC)**: (Optional but highly recommended) Code or steps to demonstrate the exploit.
- **Impact**: What could happen if this vulnerability is exploited?
- **Suggested Mitigation**: (Optional) Any ideas on how to fix the issue.

Thank you for helping keep this project secure!
