# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

## Reporting a Vulnerability

We take the security of our project seriously. If you believe you have found a security vulnerability, please report it to us by using the [GitHub Security Advisories](https://github.com/pengzaihua458-ops/NicoSaronTest/security/advisories/new) reporting tool.

### Alternate Reporting Method

If you prefer, you can email your findings to [security@example.com](<mailto:security@example.com?subject=Vulnerability%20Report&body=Please%20provide%20the%20following%20details%3A%0A%0A-%20Vulnerability%20Type%3A%0A-%20Severity%3A%0A-%20Affected%20Component(s)%3A%0A-%20Description%3A%0A-%20Steps%20to%20Reproduce%3A%0A-%20Proof%20of%20Concept%3A%0A-%20Impact%3A%0A-%20Suggested%20Mitigation%3A>).

### Preferred Disclosure Template

When reporting a vulnerability, please include:

- **Vulnerability Type:** (e.g., XSS, SQLi, SSRF)
- **Severity:** (Critical, High, Medium, Low)
- **Affected Component(s):** The part of the application affected
- **Description:** A clear and concise description of the issue
- **Steps to Reproduce:** Detailed steps to recreate the vulnerability
- **Proof of Concept:** (If available)
- **Impact:** What could an attacker achieve?
- **Suggested Mitigation:** How you think this should be fixed

## Our Response Timeline

- **Acknowledgment:** Within 48 hours of receipt.
- **Initial Assessment:** Within 7 business days.
- **Resolution:** Timeline varies by severity; we will provide regular updates.

Thank you for helping keep this project secure!
