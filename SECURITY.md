# Security Policy

## Reporting a Vulnerability

We take the security of our project seriously. If you believe you have found a security vulnerability, please report it to us immediately.

### Primary Channel

The preferred and most secure way to report a vulnerability is through **GitHub Security Advisories**:

👉 [**Report a vulnerability on GitHub**](https://github.com/pengzaihua458-ops/NicoSaronTest/security/advisories/new)

### Fallback Channel

If you are unable to use the primary channel, you may email your findings to [security@example.com](mailto:security@example.com).

To ensure a swift and accurate triage, please use the following template for your report:

```markdown
- **Vulnerability Type:** (e.g., XSS, SQLi, Buffer Overflow)
- **Severity:** (Critical/High/Medium/Low)
- **Affected Component(s):** (Specific files, functions, or endpoints)
- **Steps to Reproduce:** [Step 1], [Step 2], ...
- **Impact:** What could happen if this vulnerability is exploited?
```

## Our Response Process

1. **Acknowledgment:** Within **48 hours**.
2. **Assessment:** Within **7 business days**.
3. **Fix & Disclosure:** As quickly as possible; do not disclose publicly until a fix is released.

Thank you for helping keep this project secure!
