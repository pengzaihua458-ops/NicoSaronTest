# Security Policy

## Reporting a Vulnerability

We take the security of our project seriously. If you believe you have found a security vulnerability, please report it to us by following these steps:

1. **Do not** open a public issue.
2. Email your findings to [security@example.com](mailto:security@example.com).

### 🚀 Quick Report

[Report a Vulnerability](<mailto:security@example.com?subject=Vulnerability%20Report&body=###%20Vulnerability%20Report%0A%0A-%20**Vulnerability%20Type:**%20(e.g.,%20Cross-Site%20Scripting,%20SQL%20Injection)%0A-%20**Severity:**%20(Critical,%20High,%20Medium,%20Low)%0A-%20**Affected%20Component(s):**%20(Specific%20files%20or%20URLs)%0A-%20**Description:**%20(A%20clear%20and%20concise%20description%20of%20the%20vulnerability)%0A-%20**Steps%20to%20Reproduce:**%20(1,%202,%203...)%0A-%20**Proof%20of%20Concept:**%20(Code%20or%20screenshots%20illustrating%20the%20vulnerability)%0A-%20**Impact:**%20(What%20could%20happen%20if%20this%20is%20exploited?)%0A-%20**Suggested%20Mitigation:**%20(Optional:%20how%20you%20think%20we%20should%20fix%20it)>)

3. Use the following template for your report to help us respond quickly:

### Vulnerability Report Template

```markdown
- **Vulnerability Type:** (e.g., Cross-Site Scripting, SQL Injection)
- **Severity:** (Critical, High, Medium, Low)
- **Affected Component(s):** (Specific files or URLs)
- **Description:** (A clear and concise description of the vulnerability)
- **Steps to Reproduce:** (1, 2, 3...)
- **Proof of Concept:** (Code or screenshots illustrating the vulnerability)
- **Impact:** (What could happen if this is exploited?)
- **Suggested Mitigation:** (Optional: how you think we should fix it)
```

We will acknowledge receipt of your report and provide an estimated timeline for a fix. Thank you for helping keep this project secure!
