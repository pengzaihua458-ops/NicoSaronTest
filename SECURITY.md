# Security Policy

## Supported Versions

The following versions of this project are currently being supported with security updates:

| Version | Supported      |
| ------- | -------------- |
| 1.0.x   | ✅ Supported   |
| < 1.0.0 | ❌ Unsupported |

## Reporting a Vulnerability

We take the security of our project seriously. If you believe you have found a security vulnerability, please report it to us through the [GitHub Security Advisory channel](https://github.com/pengzaihua458-ops/NicoSaronTest/security/advisories/new).

### Fallback Reporting

If you are unable to use GitHub Security Advisories, you may email your findings to [security@example.com](<mailto:security@example.com?subject=%F0%9F%9B%A1%EF%B8%8F%20Security%20Vulnerability%20Report&body=Please%20provide%20the%20following%20details%3A%0A%0A-%20Vulnerability%20Type%3A%0A-%20Severity%3A%0A-%20Affected%20Component(s)%3A%0A-%20Description%3A%0A-%20Steps%20to%20Reproduce%3A%0A-%20Proof%20of%20Concept%3A%0A-%20Impact%3A%0A-%20Suggested%20Mitigation%3A>).

### Reporting Template

When reporting a vulnerability, please include the following information:

- **Vulnerability Type:** (e.g., SQL Injection, XSS)
- **Severity:** (Critical, High, Medium, Low)
- **Affected Component(s):** (Specific files or endpoints)
- **Description:** A detailed explanation of the issue.
- **Steps to Reproduce:** Clear, step-by-step instructions.
- **Proof of Concept:** Code or screenshots demonstrating the vulnerability.
- **Impact:** What could happen if exploited.
- **Suggested Mitigation:** How you think the issue should be fixed.

## Our Commitment

- **Acknowledgment:** We will acknowledge receipt of your report within **48 hours**.
- **Assessment:** We will provide an initial assessment of the vulnerability within **7 business days**.
- **Resolution:** We aim to resolve critical issues as quickly as possible.

Thank you for helping keep this project secure!
